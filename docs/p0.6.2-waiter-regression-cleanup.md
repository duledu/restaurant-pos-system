per run and no concurrent build/test workload:

- Bundle SHA-256: `71625f9d0499b4f2762ab99f9d9aad961006b6e8169aaf79bacf360c37287e7f`

measurements. Next router transport and actual backend latency are excluded.

proof that every historical P0.6 versus P0.6.1 difference was noise.

## Findings and decision

No reproducible, code-attributable regression was established. Do not refactor
on these three-sample medians. Direct control evidence for the five flags:

| Action | Baseline samples | After samples | Median React work before/after |
|---|---|---|---|
| Quick +1 | 17.7, 4.1, 10.9 | 10.9, 7.0, 11.9 | 5.5 / 7.6 |
| Repeat | 12.7, 22.2, 1.7 | 13.1, 9.4, 7.4 | 2.8 / 2.6 |
| Cached reopen | 53.2, 89.0, 23.7 | 45.7, 45.4, 29.7 | 38.6 / 28.3 |
| B-to-A | 37.4, 42.5, 30.6 | 26.8, 27.3, 39.2 | 32.5 / 24.3 |
| Modifier open | 4.3, 5.8, 13.5 | 5.5, 2.9, 3.0 | 4.6 / 2.2 |

All five actions produced exactly one commit per measured action in all six
sessions. No extra commit was demonstrated for the flagged actions. Quiet
polling produced zero commits and zero React work in all six sessions.

Reviewed `order-client.tsx`, `waiter-local-draft.ts`, `waiter-active-order.ts`,
and `waiter-table-memory.ts` and the P0.6-to-P0.6.1 diff:

- Quick/repeat handlers and queue were not changed by P0.6.1. The same local
  mutation path still precedes network resolution; fixture count assertions pass.
- Stable committed menu callbacks and memoized menu props remain intact.
  Search slicing is local to MenuBrowser, not invalidated by draft quantities.
- activeOrderView and table memory recompute on order changes. This predates
  P0.6.1; it is not evidence of a new regression. No additional projection
  cache was introduced to speculate about savings.
- Cached table navigation still mounts the table view and builds its projection
  and rows. That is real existing work, with substantial measured variation;
  preserving the table-owned snapshot and navigation isolation is preferable
  to changing architecture for this unproven regression.
- The inspected flag does not introduce an extra notification on an unchanged
  accepted read after inspection. Request sequence/revision/READY holds remain
  intact. Their correctness guards were not removed to save timing overhead.
- Modifier structure memoization remains keyed by item; no new handler or
  modifier-state computation was introduced in P0.6.1.

Cold-open architecture/gain preserved: **YES**. Every cold occupied sample
still used one read-only GET, never a discovery POST/detail waterfall. The
after median is 288.8 ms versus the historical pre-optimization 504.6 ms.
However, after samples were **486.2, 272.9, 288.8 ms**; baseline samples were
340.4, 276.5, 263.4 ms. The slow after sample started its GET at 95.3 ms, had
the response ready at 309.0 ms, and committed the usable order at 486.2 ms.
This unchanged-code result does not establish a hard 350 ms maximum or a
250 ms preferred target. Real-device benchmarking remains necessary.
